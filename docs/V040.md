# v0.4.0：单个应用的弹性规则

入口：「应用规则」页，搜索并点击某个应用。每个普通应用可独立选择：

| 模式 | 限制时段内行为 |
| --- | --- |
| 完全限制 | 打开即返回桌面，显示专注警示 |
| 使用后冷却 | 自定义每轮可用分钟数及到期冷却分钟数，各 1–180 分钟 |
| 始终允许（白名单） | 限制时段内也正常使用 |

空闲时三个模式都不阻止应用使用。电话、键盘、桌面和系统设置等必要交互始终保留，不可在本应用中改为限制。

## 循环规则

- 没打开应用时不开始计时；第一次打开后连续计时。
- 离开、切换应用、息屏不会暂停已开始的这一轮。
- 到期后返回桌面，并从使用截止时刻开始冷却，冷却中再次打开不会延长或重置。
- 冷却结束只恢复资格，直到下一次打开才开始新的使用时长。
- 每个应用独立存储，A 应用冷却不影响 B 应用。
- 只拦截前台使用，不是系统级强停后台进程；到期检查存在约 1 秒心跳延迟。
- 单调时钟计时不受手机日期、时间修改影响。服务重连保留状态；重启时保守进入该应用配置的完整冷却。
- 限制期间禁止修改模式、时长和白名单。编辑框提前打开，也不能在开始边界后保存。
- 空闲时修改某应用的模式或时长，清空该应用旧额度，下一次打开按新规则开始；其他应用不变。保存完全相同的规则不会重置计时。

例如短视频设置「使用 3 分钟，冷却 15 分钟」，阅读应用设置「使用 10 分钟，冷却 5 分钟」。两者分别循环，无需每天手动启动。

## 旧版迁移

v0.3.0 及更早版本的白名单、时间表、标语、最近任务设置保持。没有单应用规则字段的旧数据自动为微信创建「2 分钟使用 / 5 分钟冷却」，其他普通应用继续完全限制；旧版微信正在进行的额度 / 冷却沿用原存储。

微信也可改为完全限制、白名单或其他循环时长。微信已识别的通话页面仍单独放行，通话不开始或延长普通页面额度。真实微信来电、锁屏、多窗口及 HyperOS 兼容性仍需目标手机验证。

## 验证

纯时间测试覆盖自定义数值、精确起止、冷却结束未打开、独立应用、重连和重启语义、通话例外及 1–180 分钟参数边界。模拟器验证两个不同应用时长互不影响、设置保存、无效输入和规则锁定。另提供真实等待 1 分钟使用 + 1 分钟冷却用例：

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest '-Pandroid.testInstrumentationRunnerArguments.fullAppCycle=true'
```

本轮不依赖微信夹具验证通用规则；旧版微信分支回归可显式安装 testOnly 夹具，详见 V030。模拟器测试不能代替 HyperOS 后台策略或真实微信通话测试。
